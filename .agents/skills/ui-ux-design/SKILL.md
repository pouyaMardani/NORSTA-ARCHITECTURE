# UI/UX Design

## Understand Before Designing

- Read the project brief, roadmap, existing screens, and brand requirements before proposing UI.
- Identify the primary audience, primary user goal, and most important page action.
- Preserve established product decisions unless there is a clear reason to question them.
- Ask a concise question only when a missing requirement blocks a meaningful design decision; otherwise state reasonable assumptions.

## Information Architecture

- Give each page a clear purpose and content hierarchy.
- Make navigation labels recognizable and predictable.
- Prioritize the most important content and actions.
- Avoid adding sections, controls, or features that do not support the user's goals.
- Keep page flows consistent across related screens.

## Visual Hierarchy

- Establish hierarchy through spacing, typography, contrast, alignment, and scale.
- Make the primary action easy to identify without making every element compete for attention.
- Use whitespace intentionally.
- Align related elements and keep spacing consistent.
- Avoid visual clutter, excessive gradients, unnecessary glass effects, and decorative elements that harm clarity.

## Interaction Design

- Use familiar patterns for navigation, buttons, forms, dialogs, and galleries.
- Make controls look interactive and provide clear hover, focus, active, disabled, and loading states.
- Give users feedback after meaningful actions.
- Avoid interactions that depend only on hover, especially on touch devices.
- Provide clear empty, error, and success states where relevant.

## Content and Trust

- Use concise, useful labels and headings.
- Do not invent testimonials, customer logos, project facts, credentials, or performance claims.
- Use realistic content only when it is clearly marked as sample content.
- Make important information easy to scan.

## Responsive UX

- Design for small screens as well as desktop.
- Preserve content priority and usability at every viewport.
- Check navigation, text wrapping, image crops, and touch target sizes.
- Avoid horizontal overflow and awkward content jumps.

## Accessibility

- Prefer semantic HTML and keyboard-accessible interactions.
- Maintain readable contrast and visible focus indicators.
- Provide meaningful labels and alternative text.
- Respect reduced-motion preferences.

## Validation

- Review the actual rendered page rather than judging only the source code.
- Test key user journeys and interaction states.
- Inspect desktop, tablet, and mobile layouts.
- Record remaining limitations honestly.

## Completion Standard

The interface should help users complete the intended task clearly, comfortably, accessibly, and consistently with the product's visual identity.
